# 删除、多账户、搜索与共享规范

> 状态：用户已确定核心行为；标为“待确认 / 建议”的边界尚未确定。本文仅为设计规范，不表示已实现。
> 与 [主交互规范](APP_INTERACTION_SPEC.md) 配套；这里的状态相关删除规则优先于早期“固定四个按钮”的概括描述。

## 1. 删除行为（用户已确认）

### 1.1 媒体状态定义

- “本机存在”指系统图库中的对应媒体，不是本 App 下载的缩略图 / 预览缓存。
- “云端存在”以当前服务器、当前账户可确认的资产状态为准，不将其他账户上的副本计作当前账户已备份。
- 断网、权限撤销、资源读取失败不等于“本机不存在”或“云端不存在”。未知时不得凭缓存推测后执行危险操作。
- 共享媒体的可见性不等于所有权或删除权限。以下规则还必须与实际操作权限相交，不能允许接收方删除他人原件。

以上是落实状态驱动规则所需的安全边界，不新增跨账户联动删除能力。

### 1.2 行为矩阵

| 已确认状态 | 操作 | 影响范围 | 自动上传 | 提示 |
| --- | --- | --- | --- | --- |
| 仅本机，尚未上传 | 删除 | 仅删除本机媒体 | 已删媒体不再作为本机可上传资源；重新导入后如何识别另行定义 | 提示“尚未上传到云端”，附“不再提醒”复选框 |
| 本机与云端均存在 | 删除 | 仅删除本机，保留云端 | 不自动再次上传，除非用户手动触发 | 首次提示，附“不再提醒”复选框 |
| 本机与云端均存在 | 回收站 | 云端移入回收站，不附带本机删除 | 不自动再次上传，除非用户手动触发 | 首次提示，附“不再提醒”复选框 |
| 仅云端存在 | 回收站（替换删除按钮） | 云端移入回收站 | 后续重新出现在本机时的抑制匹配细则待定 | 与双端回收站共用当前账户的云端回收站提示偏好 |

本机删除是否进入系统“最近删除”由平台行为决定，不能伪装为 App 自有回收站。iOS 开启 iCloud Photos 时，本机图库删除可能通过系统同步影响 iCloud 和其他设备，提示必须准确，不承诺“绝不影响其他云服务”。

### 1.3 工具栏呈现

- 收藏、加相册、分享保持原有职责。
- 仅本机时显示删除；仅云端时将删除改为回收站。
- 双端都有时，底栏直接并列五项：**收藏、加相册、删除、回收站、分享**；不使用点击第三项再展开的方案。
- 仅本机底栏为收藏、加相册、删除、分享；仅云端为收藏、加相册、回收站、分享。
- 各操作需可访问的语义标签，不能仅靠两个含义接近的垃圾桶图标区分本机与云端。
- 本机独有媒体收藏先保存在本 App，系统图库按能力联动；正常上传并匹配后提交当前账户的 Immich 收藏。完整同步方向仍待定。
- 加入云端相册不能隐式上传本机原件；尤其曾同步后手动删除云端的媒体，必须先由用户明确手动上传，不采用“点击加相册即可自动代为上传”的方案。

### 1.4 防自动重传（已确认目标，具体边界待细化）

“不再上传，除非手动触发”是一项持久化的产品规则，不能只从当前上传队列移除一次。

实现必须保证：

- 决策绑定到正确的服务器、账户和媒体身份；切换账户、重启、重新扫描、自动重试不能无意绕过。
- 取消或拦截涉及同一媒体的待执行 / 重试上传，处理正在上传的竞态；操作失败不能被 UI 宣称已成功。
- 手动刷新、重新打开 App、重新开启备份不应被当成“用户手动上传该媒体”。
- 手动触发需要明确选择这张 / 这些媒体并发起上传。对于仍在云端回收站中的资产，先按服务端能力明确恢复 / 重新上传行为，不能静默造成重复资产。
- 本机删除后又从云端保存到图库、重新导入同内容或导入编辑副本时的身份匹配范围待验证；不能只靠文件名判定。
- 已确认清理范围进一步收窄为仅 App 缓存；防重传记录属于业务数据，不在清理范围内。不得因清理、重启、切回账户或重新扫描自动恢复已禁止的上传。完全移除账户 / 重置备份决策不属于清缓存，若需要应另行定义。
- 本规则在本 App 内生效，不承诺控制其他客户端或其他设备的上传。是否要求跨设备同步抑制记录需额外服务端能力，尚未确认。

### 1.5 不再提醒（已确认）

- 按服务器 + 账户 + 操作类型分别记忆，不使用跨账户全局开关。
- 独立类别为：尚未上传的本机删除、已同步后的本机删除、云端回收站。
- 仅云端与双端的回收站共用当前账户的“云端回收站”提示偏好。
- 未勾选时每次提示；勾选后跳过该账户该类别的 App 常规提示；设置提供恢复提醒。
- 此偏好不绕过操作系统强制确认、所有权校验和新增风险警告，不改变删除实际影响范围。
- 暂不承诺提醒偏好在设备间同步。

### 1.6 异常与批量操作（安全约束 / 待设计）

- 云端回收站被关闭或能力未知时，不得将“回收站”静默降级为永久删除；建议禁用该操作并解释原因，永久删除如需支持应另行设计。
- 系统拒绝本机删除、服务器拒绝回收站操作、断网和批量部分失败须分别反馈。
- 混合选择仅本机 / 双端 / 仅云端媒体时，需要按操作范围分组统计，不得用一个含糊确认框串联删除所有副本。
- 已确认云端移入回收站后，本机原件仍在就继续显示在照片流；暂定在缩略图右下角用特定状态图标区分，不能作为普通待备份项自动重传。具体图标及十五列高密度适配待原型细化。
- 曾同步、后由用户手动删除云端而仅保留本机的媒体，继续显示在照片流，用缩略图右下角专用状态图标区分，并排除自动上传；仅用户明确手动上传可触发重传。该状态与从未上传过的普通本机照片必须区分，不能把所有本机独有照片误认成已删除云端副本。
- 上述规则不因收藏、加云端相册、重新扫描或切换账户自动解除。目标云端资产不存在时不得伪造已加入云端相册；是否保存待加入意图后续确定。
- 用户从云端回收站恢复后是否继续保持禁止自动上传、如何可靠识别其他客户端产生的云端删除事件，待后续细化；网络错误不能当作删除证据。

## 2. 多服务器与多账户（用户已确认）

- 支持保存和使用多个服务器、多个账户。
- 登录界面保存曾使用的服务器及账户，便于再次选择。
- 提供按其他账户清理 App 缓存的功能；后续用户已明确只能清缓存，取代早期广义清理账户本地数据的范围。

### 2.1 必需的数据边界

- 当前浏览的账户与服务器必须清晰可见；多账户不等于跨账户混合照片流或跨服务器共享。
- 登录历史只应展示必要的地址、账户标识和显示名称；令牌等凭据使用平台安全存储，不在普通配置或日志明文保存密码。
- 首版已确认支持邮箱密码、OAuth 和 API Key；OAuth 按服务器配置提供，API Key 为高级入口。
- 保存登录历史不等于用户已同意保存密码；安全凭据持久化与自动登录的具体交互继续细化。
- 缓存、数据库、离线文件、置顶、搜索历史、备份状态和抑制重传记录按账户隔离；相同邮箱在不同服务器也不是同一账户。
- 同一服务器的不同内网 / 外网地址如何识别为同一实例，需工程验证，不能草率合并账户历史或误发令牌。
- 每项后台任务绑定创建时的目标账户，不能因界面切换而改投新账户。

### 2.2 按账户清理 App 缓存（范围已确认）

用户已明确清理只能针对 App 缓存，不再提供把业务数据混入缓存清理的广义入口。

- 可移除选定账户的可重建缩略图、预览和安全释放的临时缓存；不得删除系统图库中的用户原件或已下载原图，也不调用服务器删除资产或账户。
- 登录历史、凭据、收藏意图、相册映射和防重传记录等业务数据保留；退出 / 移除账户 / 重置决策属于单独流程，不能借清缓存执行。
- 开始前显示账户、服务器、可释放缓存空间和范围；协调正在使用文件的上传 / 下载任务，不删除未完成任务的必要数据。
- 释放已清理缓存的界面引用，不能保留悬空路径；账户隔离仍然有效，不能将一账户的缩略图暴露给另一账户。
- 不得误删其他账户仍使用的共享缓存文件。
- 主动下载原图保存至系统图库，必须完全排除在所有 App 清理入口之外；图库保存完成前的中间文件不能伪装成已成功保存的原件。

### 2.3 自动备份与账户切换（已确认）

- **只自动备份当前浏览账户**；不采用固定另一个目的地或多个账户同时自动备份的模式。
- 切换账户时暂停旧账户自动备份，按新账户自己的备份配置运行；新账户未开启备份时不能因为旧账户开启就自动上传。
- 切回旧账户时遵守其备份开关、范围和防重传记录，不能因切换清除禁止上传决策。
- 已创建任务保留原服务器 / 账户绑定，不把旧账户排队任务改投新账户；切换时停止派发旧账户新任务。
- 正在传输中的任务需要明确暂停 / 取消边界并核对远端结果，不能声称切换可以撤回已到达服务器的字节；这是工程验证项，不能让竞态导致任务投错账户。
- 前台浏览账户切换会改变自动备份运行上下文，界面应显示新目的地与旧任务暂停状态。App 退后台时是否能继续工作仍遵循系统调度，不能将此规则理解为“只有 App 前台可备份”。

## 3. 首屏功能参考与 clean-room 边界

用户要求：参考 Immich iOS 的功能，使用本 App 自有 UI。

用户已明确为搜索首屏，并决定后续再定，不阻塞照片流原型。无需现在提供截图来开始其他页面设计。

- 不读取用户提供的 GitHub `mobile/` 下 Flutter / Dart 源码，不从源码翻译 UI 或业务逻辑。
- 以官方公开产品文档、REST API、实际可见界面和用户提供的截图 / 录屏确认功能。
- 已调研材料不足以证明当前 iOS 某个具体版本的首屏模块及排列完全相同，因此不声称已经逐项对齐。

### 3.1 可供确认的功能集合（候选，不是首屏排版已确认）

| 功能 | 公开依据 | 设计边界 |
| --- | --- | --- |

## 4. 共享（用户已确认产品范围）

目标：支持目标 Immich 服务器 Web 页面面向普通用户提供的共享功能，不只实现系统文件分享。

不是把 Web 管理后台功能全部搬入 App，也不是承诺跨服务器账户直接共享。已确认 **Immich 多版本适配在 Rust 中间层完成**，不要求用户先指定固定服务器版本。Rust 统一处理接口、Schema、版本回退与能力差异，向 UI 暴露实际支持 / 不支持 / 未知及必要配置；权限不足与功能不存在不能混为一谈。以下作为跨版本能力验收基线，不宣称已完整覆盖所有版本 Web 功能。

| 功能族 | 要核对的功能 | 公开证据 / 状态 |
| --- | --- | --- |
| 同实例共享相册 | 与用户共享相册、访问已有共享相册、viewer / editor 权限、成员管理与退出 | 官方 Sharing 文档明确共享与角色；每项管理操作需目标 API / Web 验证 |
| 公开链接 | 对相册或选定媒体建立公开链接；密码、有效期、下载 / 上传许可、元数据展示 | 公开 createSharedLink API 明确支持这些字段 |
| 链接管理 | 查看已建链接、复制 / 分享、修改、撤销，以及目标 Web 可提供的媒体增减等操作 | 必须逐项核对目标版本公开 API；本轮类别页提取未返回完整端点，不伪造具体方法 |
| 自定义链接 | description 与 slug 等 Web 可提供的设置 | 当前公开创建 API 有对应字段，旧版本不保证支持 |
| 伙伴共享 | 发起 / 移除共享、查看共享来源、按伙伴控制是否纳入时间线 | 官方 Partner Sharing 文档和 Partners API；共享是有方向的，不自动互相授权 |
| 接收共享 | 访问保护 / 过期 / 撤销链接，按许可查看 / 下载 / 上传 | 密码和权限需服务端校验；App 内打开还是浏览器打开仍待确定 |

### 4.1 共享安全与自有 UI

- 相册所有者、成员角色和媒体所有者不是同一概念；editor 不能被直接解释成任意删除他人原件。
- 伙伴共享与媒体的重新公开分享可能涉及 GPS 等元数据，开启时解释共享范围，不能因同服务器就默认安全。
- 关闭下载或元数据展示不等于内容无法被截图或任何方式保存，不作防泄漏保证。
- 多账户清理或切换时，不把一个账户的共享链接管理结果误显示给另一账户。
- 公网链接应使用正确的外部访问地址，内网服务器地址不自动等于外部可访问地址；不替用户架设中转服务。
- UI 使用本 App 的四 Tab 架构；共享入口可以放相册详情和资料库 / 账户的管理分组，最终位置待原型确认。

## 6. 本机收藏（核心策略已确认，完整同步方向待定）

用户已确认：先保存本 App 本地收藏，系统图库能联动就联动，照片正常上传并匹配后，再同步当前账户的 Immich 收藏。官方能力调研见 [收藏同步可行性](FAVORITES_SYNC_FEASIBILITY.md)：iOS 有公开读写能力，Android 有标准媒体库和确认请求，鸿蒙最低 API 12 基线不能保证普通应用写回系统收藏；新版公开方法需按起始版本启用。

收藏不能隐式扩大备份范围、上传原件或解除禁止重传。完整同步方向、取消收藏传播和冲突规则由用户明确延后，不自动开展全库持续单向覆盖或双向镜像。对于手动删除云端后仅保留本机的照片，收藏或加云端相册都不触发重传；只有明确手动上传才可触发。
