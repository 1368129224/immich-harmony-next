# Agent 详细设计规范

> 用途：实施功能时的统一产品与技术契约。阅读前先读 [开发行为规范](DEVELOPMENT_RULES.md) 和根目录 `AGENTS.md`；人类概览见 [功能与 UI 设计简案](PRODUCT_UI_OVERVIEW.md)。
> **文档优先级：[功能与 UI 设计简案](PRODUCT_UI_OVERVIEW.md) 由产品负责人手工维护，是产品决策的最终依据；本文由 AI 依据简案展开为实现规范，两者冲突时以简案为准，并应同步修正本文。**
> 本文合并原交互、架构、跨平台、删除 / 账户 / 共享、收藏及调研文档。已被后续决策替代的方案不再作为有效规范。

## 1. 状态、优先级与范围

- **已确认**：用户已明确的产品要求，是实现目标，不意味着已经交付。
- **约束**：为安全、数据一致性、平台能力或 clean-room 必须满足的边界。
- **建议 / 待定**：尚未确认的方案，不擅自实现为默认行为。
- **实现现状 / 差距**：仅说明仓库中存在的代码路径或静态观察；不代替 SDK 编译、服务端和真机验收。

目标为 HarmonyOS NEXT、iOS、Android 的原生 Immich 客户端。统一功能语义、媒体状态、数据边界和品牌；返回、导航控件、菜单、分享、权限、触觉、后台执行与无障碍遵循各平台规范，不要求三端像素一致，也不分别复刻三个系统相册。

最新决策覆盖旧方案：

1. 照片默认 **4 列，双指缩放 2–15 列**（以简案为准）；此前“默认 5 列”的表述废止。
2. 查看器删除采用 **三态模型**（§6），不是此前“统一双向删除、每次只允许全删”的方案；仍不提供“只删云端并保留本机”的独立选项。
3. 第四个 Tab 使用 **资源库**，替代旧“设置 / 资料库”。
4. iOS 已有原生工程和 C-FFI，不再是占位规划；Android 仍为规划。平台目标不代表三端功能已对齐。

## 2. 信息架构与页面职责

### 2.1 四个一级目的地

照片、相册、搜索、资源库。顺序为“照片 → 相册 → 搜索 → 资源库”，当前 iOS 实现与简案一致。

- **照片**：本机 + 当前账户云端合并照片流、来源筛选、备份状态、多选与查看器。
- **相册**：本机 / 云端相册混合展示、同名合并、置顶与相册内容管理。
- **搜索**：明确范围与模式的检索、过滤和探索；首屏模块排列仍待定。
- **资源库**：分类与管理入口，不再复制一份所有照片流。人物和回收站为明确入口，不能因缺失可选 feature 字段就无声消失。

### 2.2 资源库布局

当前 iOS 已组织为：

| 分组 | 入口 |
| --- | --- |
| 常用管理 | 人物、回收站、收藏、归档 |
| 集合与分类 | 地点、本机照片、回忆、最近添加（“服务器文件夹”已确认取消，相关代码已移除） |
| 共享与访问 | 共享链接、伙伴共享、标签 |
| 相册与设置 | 合并相册偏好、照片页设置、检查更新 |
| 调试 / 版本 | 诊断记录、版本信息 |

人物来自当前服务器已识别内容，不能暗示未上传的本机照片已做人脸识别。回收站入口可见不意味着删除、恢复、永久删除等管理能力已全部实现；能力不可用应在进入或执行时明确说明，不静默改为永久删除。

原设计将账户 / 服务器 / 设置放顶栏头像入口；当前资源库保留部分设置，不在本次整理中迁移。最近添加、媒体类型、离线和备份分类是已提出的产品方向，不将所有候选入口当成已交付。

## 3. 媒体、身份与权限模型

### 3.1 身份与状态

- 本机资产身份来自系统图库；App 缓存不是本机原件。云端身份绑定服务器实例、用户和资产 ID。
- 同邮箱跨服务器不是同一账户；内外网地址是否属于同一实例需验证，不能草率合并或误发令牌。
- 已可靠匹配的同一资产合并展示；匹配不足不按文件名、日期强行去重，不轻率合并编辑版本。
- 必须区分：未上传、上传中、已匹配备份、仅云端、仅本机、传输失败、等待条件、云端回收站、曾同步后云端删除、状态未知，以及“仅有缓存”。
- 对外的四类图例“未上传 / 已上传 / 仅云端 / 仅本地”不能抹去内部状态；图标映射和优先级待原型细化。
- 断网、权限撤销、读失败或旧缓存不是资产删除证据。共享可见性也不是所有权 / 写入 / 删除权限。

### 3.2 权限与降级

- 处理完整、部分、拒绝、撤销授权，不把有限图库显示成设备空库。
- 云端浏览不依赖本机图库授权；手动上传可走系统选片，自动备份在用户主动开启时申请必要权限。
- 系统 Picker 的单次选片访问不等于未来新增照片扫描权限；URI 持久化依平台和目标 SDK 验证。
- HarmonyOS API 12 的图库受限权限需要审批及用户授权；Android 广泛媒体权限还受应用商店政策限制。
- 状态不只靠颜色，图标有语义标签；空内容、零结果、未授权、离线、认证失效、服务器错误、缩略图失败、存储不足分别说明。

## 4. 照片流与选择

### 4.1 布局、时间与分页（已确认）

- 合并本机与当前账户 Immich 资产，支持全部 / 云端 / 本机筛选。
- 正方形缩略图默认 4 列，双指缩放支持 2–15 列；相册卡片的 2–4 列上限不适用于照片。
- 状态暂定缩略图右下角图标，十五列下的可读性和触摸目标需验证，不能擅自降低上限或改位置。
- 默认拍摄时间排序，旧在上、新在下；冷启动定位整个时间线最新区域的底部，而非任意已加载分页末尾。
- 最近添加当前展示云端照片：通过 `/timeline/buckets` 与 `/timeline/bucket` 的 `orderBy=createdAt&order=desc` 按入库时间分页，保留服务端顺序，不混入本机拍摄时间或复用 `takenAt` 缓存。搜索接口 `SearchOrderField` 不支持 `createdAt`。跨来源添加时间合并仍待定。
- 回忆仅展示用户当前日历日期的历年同月同日，排除今年及未来年份；请求 `/memories?for=YYYY-MM-DD&type=on_this_day` 后，客户端再次筛选卡片与成员，不能把昨天、前天的多日可见窗口标为“今天”。
- 初次优先加载最新区域，不为了定位底部下载所有历史；补载旧内容应补偿视口位移。

### 4.2 浏览位置（已确认，含近期修复要求）

- Tab 切回、打开大图后返回保留原位置 / 原资产附近；浏览旧照片时同步新增只提示，不强制跳底部。
- 提供回到最新入口；iOS 单击已激活的“照片”Tab 不滚顶，双击平滑回到最新底部。
- 进入 / 退出多选不改变原浏览位置；底部选择栏与普通栏保持相同布局占位，不能因 safe-area inset 高度变化导致跳动。
- 缩放以双指中点附近的资产作视觉锚点。已在底部是否持续跟随新增、密度记忆、日期快速定位样式仍待定。

### 4.3 多选契约（已确认）

- 长按缩略图选中起点，可不抬手直接水平 / 斜向继续选择；建议提供显式“选择”入口和已选数量。
- 以**当前展示顺序中的连续范围**选择，不是矩形命中或只选轨迹碰到的格子。例：四列布局从 2 拖到 7，应包含 2、3、4、5、6、7。
- 每次拖动保存已有选区；回拖只撤回本轮新增范围，保留此前选择。单击已选项可取消。
- 明显竖向起手用于滚动；达到最小距离后锁定方向，在一次触摸序列中不反复切换滚动 / 选择。
- 多选固定列数，双指不触发密度变化或单指批量操作；跨屏先滚动再选择，首版无拖选边缘自动滚动。
- 取消 / 失败的手势必须释放滚动锁。不能仅在回调内 `guard isSelecting` 就认定手势不会拦截原生滚动。
- 批量操作必须显示真实成功 / 失败项；批量工具栏、全选范围、导航时选区处理等未定细节需单独确认。

**iOS 实现：** 照片页、回忆详情与相册内容网格共用连续范围选区算法；回忆和相册内容共用浏览容器，提供选择 / 取消、已选数、全选已加载项、回到最新，以及与照片页相同的分享、收藏、归档、加入相册、保存、删除工具栏。相册另有独立的“移出相册”操作。相册列表仍仅长按进入多选、点击勾选，不做拖选。范围算法目前尚无自动化行为测试（待补）；长按 / 滚动仲裁、跨屏和取消后的流畅性仍需真机验收。

## 5. 大图查看器、播放、分享与保存

### 5.1 浏览与手势

- 每次由缩略图进入默认显示工具栏；单击切换显隐，左右切图保留当前显隐；不做无操作自动隐藏。
- 提供收藏、加入相册、分享和状态驱动的删除 / 回收站；已有 iOS 还含详情、归档、存到相册和胶片条，不把占位组件反推成全平台需求。
- 区分单击与双击缩放，缩放后优先平移图片；未放大时可下拉关闭，保留可见返回入口，不抢系统边缘返回。
- 下拉关闭不得与水平分页同时进行，不出现相邻半页露出或半切换状态。iOS 当前采用 UIKit 识别器协调分页与关闭；实现细节和阈值由真机验证，不要求跨平台复用常量。
- 退场收尾按实际动画完成回调关闭查看器，不用固定延时截断弹簧；拖拽位移在未随卡片变换的坐标系中计算。取消手势回弹，不触发关闭。源码契约检查不替代真机流畅性验收。
- 信息展示包含可获取的 EXIF、日期、设备 / 镜头及地理信息；上滑抽屉为交互方案，资源不足提供重试 / 缺失说明。

### 5.2 视频与实况（已确认）

- 进入查看器后视频开始播放并显示进度条（以简案为准）；切走停止，重访重新开始播放。网格内不自动有声播放。
- 网格不自动有声播放；声音、音频焦点和具体中断行为按平台验收。
- 实况长按播放并有可见入口；动态资源缺失时准确降级为静态查看 / 重试，不伪装完整实况。
- 鸿蒙以沙箱图片 / 视频路径，经 `fileUri.getUriFromPath`、`movingPhotoManager.createMovingPhoto` 与 `MovingPhotoView` 合成显示，按目标 SDK 校验。

### 5.3 分享（已确认目标）

1. 先选原件 / 兼容副本 / 云端链接，再进入相应分享流程；文件分享走系统面板。
2. 是否保留 GPS 在设置中统一配置（默认保留），分享时自动按偏好处理，不逐次询问。去 GPS 仅处理分享副本，不改两端原件；**去 GPS 失败、格式不支持（如视频）时必须取消分享并说明原因，不得回退为分享带定位的原件**。批量分享与单张分享遵守同一偏好。
3. 原件应为真实原文件，不能以预览冒充。原件内容去 GPS 后应标注为去定位副本，不再声称字节未变。
4. 实况仍按实况分享，保留图片与动态资源关联；去 GPS 必须检查相关资源，不能只净化封面就声称整份实况净化。
5. 平台 / 接收 App 不支持实况或无法可靠净化时明确限制，由用户另选替代方式，不静默转静态或普通视频。
6. 云端链接只针对有权共享的云端资产，不隐式上传本机媒体；服务器元数据展示开关不等于净化下载原件，不能以链接满足无法落实的去 GPS 要求。
7. 大文件准备、进度、取消和格式支持需验证。当前 iOS 原件 / 去 GPS / 链接入口不代表完整兼容副本、实况净化和链接管理均已实现。

### 5.4 保存原图与缓存（已确认）

- 主动下载原图保存到系统图库，只有图库写入成功才报完成，区分原件、预览、缩略图和私有缓存。
- 走平台授权和写入机制；重复保存风险应说明。整相册下载、目标系统相册与完整去重规则待定。
- 保存保留来源关联，不解除禁止自动重传决策。
- 所有 App 清理入口只清 App 缓存，不删系统图库原件 / 已保存媒体，不调用云端删除，不删除业务数据。账户规则见 §8。

## 6. 删除与回收站

### 6.1 三态查看器契约（最新已确认）

| 可确认状态 | 底栏 | 点击后的行为 |
| --- | --- | --- |
| 仅云端存在 | 回收站，不显示删除 | 提醒移入云端回收站；提供“不再提醒”。勾选并确认后按服务器 + 账户保存偏好，后续直接执行移入回收站 |
| 本机与云端都存在 | 删除，不显示回收站 | 每次提供“仅删除本地照片”或“全部删除（本地与云端）”，不提供只删云端保留本机 |
| 仅本机、尚未同步 | 删除，不显示回收站 | 提示尚未同步，确认后仅从系统图库删除 |

- “不再提醒”只适用于仅云端的回收站提醒，不跳过系统授权、所有权检查或新的风险确认；不承诺跨设备同步偏好。
- 未知状态、读取失败、权限不可见不能直接套用表格。曾同步后云端删除的本机资产不能误提示成“从未同步”，其专用提示需细化。
- iOS 弹窗遵循系统相册 / 原生提示风格，明确取消与危险操作、按压反馈、深浅色及可访问性；当前带勾选框的是自定义仿原生面板，不称其为实际 `UIAlertController`。

### 6.2 必须明确的实现差距

按简案，“全部删除”= 删除本机并将云端移入云端回收站，是否可恢复取决于服务器配置。`deleteAssets` 不传 `force`，与此一致；界面文案使用“全部删除（本地与云端）”，不得称“彻底删除 / 不可恢复”。永久删除只出现在回收站管理中。

云端回收站可被管理员关闭、保留策略可配置。能力未知 / 不可用时，不能承诺可恢复或静默以永久删除替代“移入回收站”。恢复 / 永久删除 / 清空的入口与实现需独立验收。当前资源库回收站复用过滤网格，只能说明已有浏览路径。

### 6.3 安全与部分失败

- 删除系统图库可能进入系统“最近删除”；开启 iCloud Photos 时可能传播至其他设备 / iCloud，不能承诺仅影响此手机或保证本地彻底不可恢复。
- 删除、从相册移出、删除相册容器、清缓存不是一回事。共享角色和资产所有权需分别检查。
- 双端操作任何一端失败，分别报告已执行端与失败端；不虚报整体成功，不因另一端失败假装回滚已删除内容。
- “仅删本地”成功后必须保留云端模型，更新匹配关系；不能从时间线顺带移除云端资产。
- 批量混合来源的提示及三态组合规则未完全确定，不能把单张三态弹窗当作批量实现已完成。

### 6.4 防自动重传（已确认，边界待验证）

- 云端进入回收站或曾同步后手动删除云端、本机仍在：照片继续显示，右下角专用状态区分，不作为普通待备份项自动上传。
- 只有用户明确手动选择并上传才可触发重传。收藏、加云端相册、扫描、刷新、重启、重新开启备份、账户切回或清缓存都不解除抑制。
- 资产仍在云端回收站时，明确手动上传前须按服务端能力说明恢复或重新上传的实际行为，不能静默产生重复资产。
- 抑制记录绑定服务器、账户和可靠媒体身份，协调排队 / 重试及在途上传竞态；不能只靠文件名或从队列移除一次。
- 回收站恢复、其他客户端删除的可靠识别、重新导入 / 编辑副本 / 云端另存后的身份匹配和恢复后的抑制策略仍待验证。
- 规则只约束本 App，不承诺控制其他设备 / 客户端；跨设备抑制同步需额外能力。

## 7. 相册

### 7.1 展示、合并与身份（已确认）

- 本机与当前账户可访问的云端相册混合展示，默认两列，目标支持双指缩放至 2、3、4 列。
- 同名本机与云端相册合并为一个展示入口，可靠匹配的媒体不重复；保留底层各来源 ID，不以名称作为持久化唯一身份。
- 合并只影响展示：不自动创建云端相册、不补齐成员、不上传、不联动删除，也不因同名写入共享相册。
- 同名比较、多个同来源重名、重命名分合、封面、共享权限与操作目标仍需细化。当前实现按裁剪空白 / 忽略大小写分组，单个本机 + 单个云端时合并，是实现策略而非所有边界已确认。
- 相册内按拍摄时间混排，不按本机 / 云端分段；最新在底部，默认定位底部，不自动写回服务端相册排序设置。
- 进入具体相册（及回忆详情）后的浏览界面，其缩略图网格与导航栏 / 底部栏样式须与照片 Tab 一致：按日期的首图日期角标（≤6 列）或紧凑日期标题（>6 列）、右下角状态图标、仅对已选项显示的勾选标记、左上刷新与计数、居中标题、右上“选择 / 全选”、底部悬浮“最新”胶囊与同一批量操作栏；相册另有“移出相册”。

### 7.2 排序、置顶与管理

- 已确认按字母 / 拼音名称排序，支持固定到顶部、取消后回普通排序位置。
- 置顶组内部也按名称排序、数字自然序、同名稳定顺序为建议；多音字、符号和混合文字细则待定。置顶不自动承诺跨设备同步。
- 目标要求账户隔离。当前 iOS 置顶采用全局偏好及名称键，尚不能满足完整账户 / 稳定 ID 隔离，需后续修正。
- 创建、重命名、改封面、添加成员、移出、删除相册与删除资产分清，依据权限展示结果；相册可见不代表可编辑。
- 当前相册卡片滚动修复后采用点击进入、长按多选、点击勾选；移除卡片低距离拖拽和列表滚动禁用链。多选状态仍须可上下滚动。相册卡片 2–4 列缩放等目标需另验收，不由当前固定两列推导完成。

## 8. 多账户、认证与清缓存

### 8.1 已确认范围

- 多服务器、多账户和登录历史；登录页可选择曾使用的服务器 / 账户。
- 首版目标包括邮箱密码、OAuth、API Key，OAuth 按服务器配置提供，API Key 为高级入口；当前存在密码 / Key 等路径不代表 OAuth 已完成。
- 当前活动账户清晰可见；无跨账户混合照片流或跨服务器隐式共享。
- 数据库、缓存、离线文件、置顶、搜索历史、收藏意图、相册映射、备份配置与抑制记录都按服务器 + 用户隔离。当前部分全局偏好仍需审计。
- 凭据用安全存储；自动登录、凭据失效与移除账户完整流程另行细化，不把清缓存当退出登录。

### 8.2 清理范围

- 可清选定账户的可重建缩略图、预览及可安全释放的临时文件。
- 不删系统图库、已保存原图、云端资产、登录历史、凭据、收藏意图、映射与防重传记录。
- 开始前说明账户、服务器、范围和可释放空间；协调读写 / 上传 / 下载中的文件，更新失效引用，不误删其他账户共享文件。
- 图库保存中的中间文件不是“已保存原图”；不可因清理造成任务数据丢失而仍报成功。

### 8.3 账户切换与任务绑定

- 只自动备份当前浏览账户，不设置另一个固定目的地或多账户并行自动备份。
- 切换暂停旧账户新任务派发，按新账户自己的开关 / 范围运行；新账户未开启时不沿用旧开关。
- 所有任务绑定创建时账户 / 服务器，不改投；切回遵守原配置和抑制记录。
- 在途取消 / 暂停需核对远端结果，不能承诺撤回已上传字节；后台能力受系统调度限制，不等于仅前台可运行。

## 9. 自动备份

- 已确认首发包含自动备份，不以手动上传或纯浏览替代。
- 默认不开启；用户先选本机相册，再开启当前账户备份，覆盖所选已有及新增照片 / 视频。
- 默认仅 Wi-Fi、不要求充电，移动数据默认关闭；允许修改条件，不扩大相册范围。
- 展示待备份、上传中、等待 Wi-Fi / 电量 / 系统调度、失败、完成；暂停原因真实，不承诺精确剩余时间或锁屏 / 系统终止后即时完成。
- 校验和预检、原件提取、实况图片 + 动态轨道完整性、失败重试、重复任务和抑制记录需共同验证；静态轨上传成功不算完整实况备份。
- 选片范围、图库授权不足、存储 / 网络失败及系统后台限制提供准确降级与手动继续。
- 相册映射同步另定，不因同名合并自动上传到同名共享相册。

## 10. 收藏

区分 **系统图库收藏、本 App 收藏意图、当前服务器账户的 Immich 收藏**，不使用一个布尔值代表三者均已同步。

已确认策略：

1. 本机独有媒体先可靠保存 App 收藏意图，可离线。
2. 系统具备公开 API、权限且用户同意时联动系统收藏；不具备时明确仅为 App 收藏。
3. 媒体按原备份规则正常上传并可靠匹配后，提交当前账户收藏意图；失败保留重试状态。
4. 收藏不触发原件上传、不扩大备份范围、不解除抑制；云端独有也不为联动系统收藏而隐式下载到图库。
5. 目标云端资产不存在时不能伪造加入相册；需独立手动上传，是否保存待加入意图待定。

平台能力与证据边界：

| 平台 | 读取 / 写入 | 限制 |
| --- | --- | --- |
| iOS | `PHAsset.isFavorite` / `PHAssetChangeRequest.isFavorite` | 仅授权资产，变更须检查系统结果；不承诺每次可后台静默写入或每次必弹确认 |
| Android | API 30 起 `IS_FAVORITE` / `MediaStore.createFavoriteRequest` | 系统请求完成后才算成功；旧版降级，不保证 OEM 私有收藏一致 |
| HarmonyOS NEXT | `PhotoKeys.FAVORITE` / 系统收藏相册可按权限读取 | API 12 普通应用系统收藏写回不可保证；较早接口有系统限制，公开新版 `setFavorite` 文档标注 26.0.0 起，按目标 SDK 重新核验 |

完整同步方向、系统收藏导入、云端回写系统、取消收藏传播、首次冲突合并仍待定；不擅自实现全库双向镜像或“任一端为真永远为真”。系统收藏不按 Immich 账户隔离，不能自动把 A 意图传播到 B；离线变更归并最终意图，未知不能当未收藏来批量清除。

## 11. 搜索与共享

### 11.1 搜索

- 功能参考公开 Immich iOS / Web 能力，使用本 App 自有 UI，不读取官方客户端源码。
- 首屏排列后定，不阻塞照片流。候选为搜索框、人物 / 地点探索和筛选。
- 区分元数据过滤与语义检索，明确账户、范围和模式。基础候选包含日期、类型、相册、文件名、描述、标签、OCR、相机等，逐项按服务端版本验收。
- 中文语义能力依赖模型、配置和索引；配置关闭、权限不足、索引未完成、网络失败与真零结果不同。
- 搜索历史目标按账户本地保存并可清空；相关性与时间排序、未上传本机内容的搜索范围需细化。

### 11.2 共享能力目标

目标为当前服务端 Web **普通用户**共享能力，不包括管理后台全部功能，也不承诺跨服务器共享。

| 功能族 | 验收范围 |
| --- | --- |
| 共享相册 | 已共享相册访问、创建共享、viewer / editor、成员管理 / 退出，逐项验证权限 |
| 公开链接 | 相册或指定媒体创建，密码、有效期、下载 / 上传许可、元数据展示 |
| 链接管理 | 列表、复制 / 分享、修改、撤销、媒体增减及目标版本支持的 description / slug |
| 伙伴共享 | 有方向的发起 / 移除、查看来源、是否纳入时间线，不自动互相授权 |
| 接收共享 | 密码、过期 / 撤销处理、按许可查看 / 下载 / 上传；App 内或浏览器打开仍待定 |

约束：

- editor、相册所有者与资产所有者不是同一概念；不得推导任意删除他人原件。
- 关闭下载 / 元数据显示不保证防截图或防保存；伙伴共享和再次公开涉及 GPS 风险，应说明范围。
- 使用可用外部地址，不把内网地址当公网链接，不擅自架中转。
- 账户切换不泄漏另一账户的共享结果；版本差异集中 Rust，权限 / 能力 / 未知分别反馈。
- 当前已有共享浏览入口和局部分享代码，不等于上述管理闭环全部完成。

## 12. 技术架构与接口契约

### 12.1 数据流与模块

```text
HarmonyOS ArkUI V2 ── immich-ohos-napi ─┐
                                      ├── immich-core ── Immich REST API
 iOS SwiftUI/UIKit ── immich-ios-ffi ───┘       │
       │                                     └── SQLite / 沙箱缓存
       └── PhotoKit / 原生权限 / 分享 / 后台任务
Android：原生层与独立桥接尚需规划，不复用鸿蒙 N-API
```

核心文件：

- `crates/immich-core/src/{client,adapter,db}.rs`：HTTP、响应适配、持久化。
- `crates/immich-ios-ffi/{src/lib.rs,include/immich_core_ffi.h}`：`immich_ios_*` 导出与 `immich_ios_free_string`；JSON envelope 的字段和签名以实际头文件为准。
- `ios-app/Runner/ImmichCoreBridge.swift` 与 `Runner-Bridging-Header.h`：Swift 接入；`NativeImmichApp.swift` 为主时间线 / 查看器，`NativeFeatures.swift` 为相册 / 搜索 / 资源库等，`NativeLibrary.swift` 为集合 / 人物等，`NativeCloudStatus.swift` 为匹配状态，`NativeBackupEngine.swift` 为平台备份。
- `harmony-app/entry/src/main/ets/`：bridge、models、pages、components；Mock 与 Native 分开验证。

当前 iOS 仍含 Swift 直连 HTTP。上图是分层目标，不表示全部 HTTP / 业务已迁移 Rust。

### 12.2 Rust 缓存与数据库

- `server_config`、`buckets`、`assets` 等存配置、时间桶和资产；资产包含日期、实况关联、ThumbHash、EXIF 及缓存路径，按桶与创建时间索引。实际 Schema 及后续备份 / 抑制记录以 `db.rs` 为准，不把旧文档表结构当迁移脚本。
- 缓存下载先检查非空文件，未命中写临时文件，完成后原子 rename，再记录路径，避免半文件被渲染。并发请求的临时文件、取消和竞态必须验证。
- `thumbnail`、`preview`、视频和原件分清；OS 图片显示使用有效沙箱路径，清理后释放引用。

### 12.3 Immich 多版本兼容

以下为已有架构中的接口族 / 兼容基线，不是对所有版本的保证；以公开 API、当前代码和目标服务器测试为准，不把历史文档中的“新版”标签当版本事实。

| 场景 | 契约 / 兼容基线 |
| --- | --- |
| 鉴权 | `x-api-key` 或 `Authorization: Bearer`；健康 / 版本探测涉及 `/api/server-info/ping`、`/api/server/version` 等历史差异，重新验证实际版本 |
| 时间桶 | `/api/timeline/buckets` 优先 `visibility=timeline&withPartners=true`；HTTP 400 时回退 `size=MONTH&isArchived=false` |
| 桶内容 | `/api/timeline/bucket` 用 untagged `RawBucketResponse` 支持列式对象与对象数组，统一为资产模型 |
| 图片 | `/api/assets/{id}/thumbnail?size=thumbnail|preview`，旧版本可能 `/api/asset/thumbnail/{id}` |
| 视频 | `/api/assets/{id}/video/playback`，原件回退 `/api/assets/{id}/original`，不冒充相同质量 |
| 详情 | `/api/assets/{id}`，提取可用 `exifInfo` |
| 上传 | 校验和预检、multipart、实况双轨及错误结果；具体端点 / DTO 以公开契约和 Rust 实现为准 |
| 搜索 / 人物 / 共享 / 回收站 | 按目标版本能力验证请求、分页、权限和数据结构，不能由入口存在推断 API 可用 |

列式示例为 `{ "id": ["a"], "type": ["IMAGE"], "fileCreatedAt": ["..."] }`，旧数组为 `[{ "id": "a", "type": "IMAGE", "fileCreatedAt": "..." }]`；长度、可空字段与 EXIF 缺失均需测试。不得保留旧文档“节省 70% / 零开销 / 所有链路已验证”等无当前证据的性能结论。

N-API 能力包括初始化、登录、时间桶同步 / 资产查询、缓存、查看器媒体 bundle 与 EXIF；JS 导出命名和 DTO 以生成的 `index.d.ts` 为准。FFI 必须明确空指针 / 错误 / 释放契约，网络与 IO 不在 UI 主线程运行。

## 14. 验收用例

1. 今天导入十年前照片：拍摄时间归位，最近添加按正确入库语义查找，不以缓存下载时间替代。
2. 本机仅授权三张但云端正常：仍可浏览云端，明确有限授权，不误报设备空库。
3. 四列示意从 2 拖到 7 再回 4：连续范围可预测、保留原选区，竖向起手仍滚动，多选不缩放。
4. 浏览旧照片时同步、缩放、切 Tab、开大图返回、切换多选：不无故跳到最新或改变视口位置。
5. 相册正常 / 多选上下滑、慢滑、取消触摸、返回相册：均不残留滚动禁用状态。
6. 下拉关闭大图不半页露出；视频进入后开始播放并有进度条；实况缺轨不报完整播放 / 备份。
7. 三种来源的单张删除逐一核对按钮、提示和实际删除端；仅删本地后云端保留，取消不变更数据。
8. 回收站关闭、只读资产、断网、系统拒绝和双端部分成功：分别反馈，不静默永久删除或报整体成功。
9. 云端删除后仍有本机原件：继续显示且不自动重传，收藏 / 加相册 / 清缓存 / 切账户不解除抑制；仍在回收站时手动上传先明确恢复 / 重传行为，不静默制造重复。
10. 切账户：无缩略图、搜索历史、置顶和旧任务目的地串用；新账户未启用备份不上传。
11. 下载写图库成功才报完成；清缓存不删原件、凭据或业务决策；去 GPS 不改源文件且不虚报实况净化。
12. 大字号、读屏、深浅色、减少动态效果下可完成选择、返回、分享与危险确认。
